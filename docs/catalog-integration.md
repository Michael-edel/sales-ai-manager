# Подбор товаров в заявке Michael

Основное рабочее место — заявка в AI-менеджере. Локальный «Кабинет Michael» остаётся источником каталога собственного склада и предложений поставщиков. Первая версия соединяет их через версионированный экспорт; постоянная синхронизация ещё не включена.

## Сценарий менеджера

1. В локальном кабинете открыть «Поставщики» → «Экспорт для AI-менеджера».
2. Администратор AI-менеджера открывает заявку, блок «Подбор товаров из заявки» → «Загрузить каталог из кабинета» и выбирает экспортированный JSON.
3. Нажать «Взять позиции из заявки», проверить распознанные наименования, количества и единицы. Поддерживаются явные количества в конце строки и столбцы с разделителями. Нераспознанное количество остаётся пустым.
4. Найти предложения, выбрать точные товары, распределить количество между складом и поставщиками. Например, из необходимых 10 штук взять 3 со склада и 7 у поставщика.
5. Указать нужную дату, продажную цену или целевую маржу, подтвердить неизвестные налоговые условия по документу и точную модель/единицы.
6. Пересчитать и сохранить черновик. Новая версия каталога требует явного пересчёта и повторной проверки. Конфликт редактирования не перезаписывает чужой подбор.

## Расчёт и источники

- Остаток собственного склада отделён от остатка поставщика. Суммарное количество одного предложения проверяется по всей заявке.
- Код 1С, артикул и бренд — отдельные поля. Подтверждённая связь товаров позволяет найти предложения других источников по коду 1С, даже когда наименования различаются.
- Обычное сходство названий — кандидат, а не доказанное совпадение. Технические параметры и единицы проверяет менеджер. Неявных преобразований упаковок в штуки нет.
- Закупка всегда берётся из серверного снимка, а не из данных браузера. Продажа: ручная цена → розничная из источника → расчёт по целевой марже, если доступны все условия. Закупка не подставляется вместо продажи.
- Выручка, закупка и прибыль рассчитываются в KZT без НДС. Маржа = прибыль / выручка. Наценка и маржа различаются. Введённая доставка — сумма без НДС за выбранное количество этого предложения; её нужно распределить по позициям, чтобы не учитывать одну перевозку несколько раз.
- Неизвестный НДС, валюта, цена или доставка не становятся нулём. Без стоимости доставки видна только маржа товара. Автоматического валютного пересчёта нет.
- Для «Светотехника-1» используется среда и крайний срок заказа в пятницу 15:00, часовой пояс Экибастуза `Asia/Almaty`. На момент наступления крайнего срока выбирается следующая доступная поставка. Это плановая дата, не подтверждение отгрузки.
- Для 220VOLT известны бесплатные понедельники, но неизвестен крайний срок; точную дату система не обещает. Неизвестные условия остальных поставщиков требуют уточнения.
- Снимок старше 24 часов помечается как устаревший. Сохранённый расчёт старше 15 минут, при смене снимка или изменении рассчитанной даты доставки получает отметку необходимости пересчёта при открытии заявки.
- Источник `nkt` — тестовая 1С. Такой каталог остаётся тестовым и не подтверждает доступность рабочего склада. Физический остаток не учитывает резервы.

Подбор не резервирует товар, не создаёт документы в 1С, не размещает заказы поставщикам и не отправляет предложение клиенту. Полностью автоматическое распределение по оптимальному сценарию и постоянное обновление каталога — следующие этапы; текущий подбор подтверждает менеджер.

## Доступ и хранение

Текстовую заявку можно создать кнопкой «Сохранить заявку для подбора» без вызова ИИ и 1С. Исходный текст сохраняется буквально, запись имеет `source_type=text_draft`, анализ ожидается отдельно. Повтор сохранения с тем же ключом возвращает ту же заявку; другой текст с тем же ключом отклоняется. Для этого пути нужна добавочная миграция `0021_request_draft_submissions.sql`. Создаются только внутренние задачи проверки позиций и подбора.

Экспорт сохраняет явно указанную базовую единицу, включая характеристику «Базовая единица» на сайте поставщика. Ручное изменение или очистка имеют приоритет. Противоречивые единицы не угадываются. Для старых текстовых заявок убираются только узнаваемые метаданные и полностью распознанные конечные сообщения недоступности 1С; неопределённый служебный текст остаётся для проверки, чтобы не потерять товарные строки.

Подбор, закупочные цены и маржа доступны только `admin` и `manager`. Импорт доступен только `admin`. API использует существующую сессию; изменяющие запросы требуют Origin этого приложения.

JSON содержит частные цены и остатки, но не настройки подключения, ключи, пароли, клиентов или заявки. Его нельзя включать в Git или публичную статическую сборку. Локальный `dist/index.html` кабинета не копируется в AI-менеджер. Полный каталог хранится в закрытой D1; в интерфейс поиска возвращаются только ограниченные результаты.

Импортируется до 100000 предложений, файл до 100 МиБ, пакеты до 100 предложений и 2 МиБ на HTTP-запрос. Старый каталог остаётся активным до полной загрузки нового. Повтор одинакового пакета безопасен. Исторические снимки и сохранённые расчёты сохраняются; автоматическая очистка старых импортов пока отсутствует — перед частой синхронизацией нужно добавить политику хранения.

## Развёртывание

Код подготовлен в ветке `codex/catalog-request-matching`. Перед рабочим включением нужны разрешение владельца на публикацию, сборка frontend и применение добавочной миграции `worker/migrations/0020_catalog_quotations.sql`. Миграция добавляет таблицы каталога и подбора, не изменяет исходные товары/документы 1С. Выкладывать содержимое `data/` или `.dev.vars` нельзя.

Существующий workflow публикации запускается при push в `main`; не использовать его для пробного запуска. Проверки pull request выполняются отдельным workflow без доступа к облачным секретам. При откате интерфейса новые таблицы и сохранённые данные можно оставить; удаление таблиц уничтожит подборы и историю.

Локальная проверка на отдельной D1, команды PowerShell в одну строку каждая:

```powershell
Set-Location -LiteralPath 'D:\мои документы\ChatGPT\sales-ai-manager-integration\frontend'; npm ci; npm run build
```

```powershell
Set-Location -LiteralPath 'D:\мои документы\ChatGPT\sales-ai-manager-integration\worker'; npm ci; npm run typecheck; npm test; npm run d1:migrate:local; npx wrangler dev --local --ip 127.0.0.1 --port 8787
```

Для нового локального пользователя задайте `ACCESS_PASSWORD` в исключённом из Git файле `worker/.dev.vars`; рабочие пароли сюда не копируются.

## Проверки первой версии

- Unit-тесты: отдельные цены, НДС, маржа и наценка, недостаток/перераспределение остатков, изменение сроков, неизвестные данные, подтверждённые связи.
- API-тесты исполняют настоящие SQLite-запросы и миграцию: роли, атомарный импорт, повтор пакетов, ревизии, конфликт каталога, сохранение события вместе с подбором.
- Реальный локальный Worker + D1 + браузер: заявка 10 шт, распределение 3+7, прибыль 4300 ₸ и маржа 43% на искусственных ценах, дата поставщика 04.11.2026 при проверке 27.10.2026, сохранение и повторное открытие, экран 390 px без горизонтального переполнения.
- Реальные локальные файлы каталога проверены в памяти: 43785 предложений прошли контракт импорта. Эта проверка не включает дополнительные изменения, которые существуют только в IndexedDB открытого кабинета. Сам JSON не сохранён в репозиторий и не передан в облако.
