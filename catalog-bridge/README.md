# Каталог кабинета Michael → AI-менеджер

Первая связь между проектами — перенос снимка каталога для подбора заявки. Этот модуль ничего не пишет в 1С, не вызывает API поставщиков и не создаёт заказов или резервов.

## Как перенести данные

1. В локальном кабинете откройте **Поставщики → Экспорт для AI-менеджера**. Кнопка читает актуальные сохранённые товары и подтверждённые связи из IndexedDB этого браузера.
2. В AI-менеджере откройте подбор заявки и импортируйте полученный `Michael_catalog_YYYY-MM-DD.json` через действие импорта каталога администратора.
3. Проверьте дату снимка. После обновления цен, остатков или связей повторите экспорт и импорт.

Рабочая база кабинета сейчас — **тестовая 1С `nkt`**. Снимок помечается `environment: "test"`; наличие источника `warehouse:onec-nkt` не позволяет переименовать его в боевой. Предложения поставщиков остаются отдельными от собственного склада. Подтверждение заказов и расчёт резервов в этой версии отсутствуют.

## Что передаётся

Версия контракта1: `schemaVersion`, `sourceSystem`, `exportedAt`, `environment`, `offers`. Каждое предложение содержит идентичность товара, наименование, артикул, бренд, отдельный код 1С, единицу, источник, склад, количество/наличие с признаком подтверждения и датой, три независимые цены и известные условия поставки. Цены состоят из `amount`, `currency`, `vatIncluded`, `vatRate`, `updatedAt`. Полный перечень полей виден в `export.mjs` и проверяется тестами.

- `productId` объединяет товары только по сохранённой ручной связи с **двумя** признаками `confirmed: true` и `unitConfirmed: true`. Автоматические предположения по бренду/артикулу не становятся подтверждёнными связями.
- Неизвестная единица — пустая строка; неизвестные количество, цена, НДС и дата — `null`. SKU, равный названию в старом XLS «Светотехника-1», не превращается в артикул. Код 1С передаётся отдельно от артикула. UUID вместо бренда удаляется; `SIRIUS` и `Sirius` приводятся к `Sirius`.
- Ручные название, артикул, бренд, розничная цена и единица сохраняются. Налоговые условия ручной розничной цены неизвестны, пока их не подтвердят. Ставка НДС не выводится из календаря: для 1С, 220VOLT и «Светотехника-1» подтверждено только включение НДС, `vatRate` остаётся `null`.
- Цена 1С экспортируется только при согласованном снимке остатков/цен и единственном варианте без упаковки и характеристики. Неоднозначную цену потребуется выбрать отдельно. Дата исходных данных имеет приоритет над датой ручной правки товара.
- Положительный физический остаток 1С ещё не означает свободный остаток: резервы и доставка покупателю не учтены. Устаревший/неподтверждённый остаток не подтверждает доступное количество. Удалённые поставщики исключаются.
- Для «Светотехника-1»: доставка бесплатно по средам в Экибастуз, заказ до15:00 предыдущей пятницы (`Asia/Almaty`). Для 220VOLT: бесплатно по понедельникам, крайний срок неизвестен — дата требует уточнения. Условия Azerti, ELCO.KZ и других поставщиков не выдумываются.

Настройки, пароли, API-ключи, клиенты, заявки, изображения, описания, сырые ответы источников и доказательства ручных связей в файл не копируются. Однако сам снимок содержит частные закупочные цены и остатки: храните его локально и импортируйте только в свой AI-менеджер; не добавляйте в Git.

## Резервный способ без браузера

Если есть актуальная локальная JSON-резервная копия кабинета, можно преобразовать её без сетевых запросов. В PowerShell из корня проекта одной строкой:

```powershell
node .\catalog-bridge\convert-backup.mjs --input 'D:\private\Michael_backup.json' --output 'D:\private\Michael_catalog.json'
```

Существующий выходной файл не перезаписывается. Этот способ переносит состояние на дату резервной копии; основным остаётся экспорт из работающего кабинета.

## Разработка и проверки

`export.mjs` — переносимый модуль без зависимостей. Его побайтовая копия находится в кабинете в `src/ai-catalog-export.js` и подключается локальной сборкой `build.mjs`. При изменении контракта обновляйте обе копии и соответствующие тесты; файлы частных снимков в кодовую базу не входят.

```powershell
node --test .\catalog-bridge\export.test.mjs
```

Тесты используют только искусственные товары: проверяют отсутствие приватных полей, явное подтверждение связей/единиц, разделение артикула и кода, тестовую среду, цену упаковки, ручные правки, неизвестные налоги, расписание и устаревшие остатки.
